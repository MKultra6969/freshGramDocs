# freshGram: документация плагинов

Документация по системе плагинов freshGram, форка клиента Telegram Desktop. Она описывает бета-версию: имена, сигнатуры, лимиты и поля манифеста могут меняться между сборками.

Страницы лежат в Markdown-файлах в `content/ru/`. Сайт собирается на Vite, React и TypeScript, стили написаны на обычном CSS. В Docker-образе статику раздаёт nginx.

- Клиент freshGram: https://github.com/Snowy-Fluffy/freshGram
- Автор документации: [MKultra6969](https://github.com/MKultra6969)

## Запуск

| Вариант | Команда | Адрес |
|---|---|---|
| Docker, nginx (production) | `docker compose up -d docs` | http://localhost:7517 |
| Docker, dev-сервер | `docker compose --profile dev up dev` | http://localhost:5173 |
| npm, dev-сервер | `npm ci`, затем `npm run dev` | http://localhost:5173 |

После правок в образе `docs` пересоберите его: `docker compose up -d --build docs`. Dev-контейнер монтирует исходники, поэтому правки видны сразу.

Нужен Node.js 24, как в `Dockerfile`. `npm run build` проверяет типы через `tsc --noEmit` и собирает сайт в `dist/`.

## Добавление страницы

Создайте файл `content/ru/<имя>.md`. Адрес страницы задаёт поле `slug`, имя файла на него не влияет. Обязательны только `title` и `slug`: без них сборка падает.

```markdown
---
title: "Название страницы"
description: "Краткое описание."
section: "Возможности"
order: 20
slug: "my-page"
status: "экспериментально"
---
```

- `title`: заголовок страницы и название в меню.
- `slug`: адрес, страница открывается по `#/<slug>`. Допустимы латинские буквы, цифры, `-` и `_`. Первый символ обязан быть буквой или цифрой (регулярное выражение `^[A-Za-z0-9][A-Za-z0-9_-]*$`). Одинаковый `slug` у двух страниц ломает сборку. Страница `introduction` открывается по умолчанию.
- `description`: описание под заголовком. Попадает также в `llms.txt` и в Markdown-файл страницы.
- `section`: раздел в меню; без него страница попадает в раздел «Прочее», он выводится последним. Задавайте всегда.
- `order`: число; страницы внутри раздела идут по возрастанию; без `order` страница в конце раздела. Внутри одинакового `order` порядок по `slug`.
- `status`: `стабильно`, `экспериментально` или `WIP`. Выводится бейджем под заголовком. Регистр важен: `wip` не совпадёт с `WIP`. Любое другое непустое значение тоже выводится, но с общим значком (Info). Пустой `status` бейджа не даёт.

Порядок разделов задан списком `SECTION_ORDER` в двух файлах: `src/content/loader.ts` и `scripts/build-llms.mjs`. Если меняете порядок или добавляете раздел, правьте оба.

## Версия документации

Значения лежат в `src/version.ts`: `DOCS_VERSION` (сейчас `7.5.10`), `DOCS_CHANNEL` (`beta` или `stable`) и `DOCS_VERSION_LABEL` (строка на странице введения, сейчас `7.5.10 beta`).

Если есть исходники клиента, обновите значения командой `npm run sync-version`. Путь к корню исходников передаётся в переменной `FRESHGRAM_SRC`: `FRESHGRAM_SRC=<путь> npm run sync-version`. В PowerShell: `$env:FRESHGRAM_SRC="<путь>"; npm run sync-version`. Скрипт читает файл `Telegram/build/version`: `AppVersionStr` даёт номер, `BetaChannel 1` даёт канал `beta`, иначе `stable`.

Без исходников значения правятся в `src/version.ts` вручную.

## Структура

- `content/ru/`: страницы документации.
- `src/`: приложение, компоненты и стили.
- `scripts/`: сборка файлов для ИИ-агентов и синхронизация версии.
- `public/`: статика. Файлы `llms*.txt` и каталог `md/` создаются при сборке и в git не попадают.
- `DESIGN.md`: визуальная система. Новые стили и компоненты берут значения оттуда.
- `Dockerfile`, `docker-compose.yml`, `nginx.conf`: образ и раздача статики.

## Деплой

Nginx в контейнере слушает порт 80, наружу он опубликован как 7517 (`7517:80` в `docker-compose.yml`). Чтобы открыть сайт по домену, настройте обратный прокси, например Nginx Proxy Manager. Прокси должен пересылать запросы домена на `http://localhost:7517`. Если прокси стоит на другом сервере, вместо `localhost` укажите адрес хоста.

## Файлы для ИИ-агентов

Сборка создаёт Markdown-версии документации, чтобы агентам не приходилось разбирать HTML:

- `/llms.txt`: индекс разделов со ссылками на страницы.
- `/llms-full.txt`: вся документация одним файлом.
- `/md/<slug>.md`: одна страница.

Файлы создаёт `scripts/build-llms.mjs`. Он запускается перед `dev` и `build` через скрипты `predev` и `prebuild`. Руками их не правьте: при каждой сборке они создаются заново. На каждой странице есть кнопки «Скопировать для ИИ» и «Скачать .md» с тем же текстом.
